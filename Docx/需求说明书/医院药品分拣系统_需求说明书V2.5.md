# 医院药品分拣系统 需求说明书 (基于落药检测闭环版)

版本：V2.5

编制日期：2026-10-09

版本说明：本版依据当前已实现系统编写，与 V2.4 的主要变化：

1. 明确单人使用定位：取消管理员/药师/操作员三种角色的菜单权限过滤，登录后全部菜单可用；移除账号管理界面，系统仅保留初始管理员账号登录；
2. 待配任务队列并入配药监控看板：加入队列（录入区）、置顶、撤销、历史查询都在看板完成，独立“待配队列”页面移除，导航减为 4 项（配药看板 / 药品与工位 / 处方模板 / 系统日志）；
3. 看板删除工位作业方向指示（左药位/分拣槽/右药位三个高亮方块与提示文字），机械臂作业方向改写入看板日志；
4. “系统运维”页去掉 Tab 壳与人员权限页签，仅保留系统日志查询，导航更名为“系统日志”；
5. 沿用 V2.4 期间的调整：药品字典与工位指令合并为“药品与工位”页（上下分区布局）。

## 1. 项目背景与目标

### 1.1 项目背景

医院药房传统配药流程依赖人工按处方逐一取药，效率低、易出现药品拿错的风险，且缺乏配药过程的数据记录，一旦出现问题难以追溯具体环节。

本项目设计并实现一套医院药品分拣系统。考虑到实际开发成本与硬件约束，系统通过上位机软件控制 3D 打印双轴机械臂，利用机械臂控制器内已固化的“预设动作组”宏指令完成药品的抓取与分拣放置。系统将处方（任务）信息、机械臂执行状态、落药检测结果及异常停止过程全程记录到数据库，实现配药流程的半自动化与可追溯。

V2.3 及更早版本中，取药后的数量核对依赖人工在弹窗中清点，并配套“漏抓自动补缺、多抓强制物理剔除”的纠偏机制。V2.4 起，系统引入落药检测通道（独立串口的落药传感器，或可配置成功率的模拟实现）：每次投放后自动确认这一盒药是否掉进分拣槽，未检测到落药时自动补抓，取消了对每种药品的人工清点环节。

### 1.2 项目目标

- 基于控制板预设的三组作业方向（前、左、右），实现机械臂根据任务自动完成“触发特定方向抓取 → 触发正前方分拣槽放置”的动作序列。
- 建立药品与固定物理工位（左药位/右药位）的映射关系。
- 落药检测闭环：每次投放确认一次落药；未检测到落药自动补抓；连续漏抓达到上限时停止并判为传感器异常。
- 记录每条机械臂宏指令的下发状态，提供任务级别的配药进度与完成状态跟踪。
- 任务完成后需人工确认取走分拣槽药品，方可继续连续配药。
- 中断恢复：急停或程序退出后，从数据库记录的进度继续，只补抓剩余数量，不重复已完成抓取。

### 1.3 适用范围

本系统面向课程设计/毕业设计/个人练习项目场景。物理场景限定为 1 个分拣槽、2 个药品货位和 1 条落药检测通道。上位机保存 `$DGT` 动作组编号，真正发给控制板的是对应动作帧里的 `#000P1500T1000!` 舵机指令。系统不涉及六轴实时角度逆解计算与底层的防撞轨迹规划。

## 2. 项目范围

### 包含内容

- 上位机软件（C# WinForms + SQL Server 开发环境）
- 固定处方维护（模板处方，可反复选用）
- 待配任务队列（加入 / 置顶 / 撤销 / 历史查询 / 再次配药，全部在配药监控看板操作）
- 药品字典的基础数据维护与软删除管理
- 登录认证（单一管理员账号，单人使用，登录后全部菜单可用）
- 药品与固定物理工位（左、右）的绑定维护
- 工位抓取指令、放置指令与动作延时配置（与药品字典合并为“药品与工位”页）
- 基于预设宏指令的串口通信触发与固定动作延时控制
- 落药检测闭环（传感器串口 / 成功率模拟两种实现）
- 配药执行状态跟踪、中断恢复与传感器异常拦截
- 指令下发与操作日志记录、查询和 Excel 导出

### 不包含内容

- 六轴机械臂底层驱动与空间三维坐标系的标定算法开发
- 多机械臂协同调度
- 多角色账号管理界面（单人使用的上位机只保留初始管理员账号，不再提供账号新增、角色调整与启停维护）
- 真实药品识别/称重传感器算法开发（V2.4 起用落药检测信号确认“盒数”，“是什么药”仍由药品货位绑定关系保证）

## 3. 术语定义

| **术语**   | **说明**                                                     |
| ---------- | ------------------------------------------------------------ |
| 上位机     | 运行本系统的电脑端软件，负责业务逻辑控制、数据存储与宏指令触发下发 |
| 预设动作组 | 机械臂控制器内预先烧录好的连贯动作序列（如 `G0003-G0007` 组成的一个完整“前抓”动作流） |
| 固定工位   | 机械臂动作预设所能覆盖的 3 个有效作业区域：正前分拣槽、左侧药位、右侧药位 |
| 触发宏指令 | 工位表中保存的动作组编号（如 `$DGT:13-17,1!`）。控制板不能直接执行该字符串，上位机发送前要展开成 G0013 至 G0017 的舵机帧 |
| 固定处方   | 可反复选用的配药模板。只保存处方名称和明细（药品 + 数量），不绑定患者，也不记录某一次配药进度 |
| 待配任务   | 由固定处方生成的一次配药记录。患者编号、队列顺序、配药状态和抓取进度都记在任务上 |
| 落药检测传感器 | 检测药品是否落入分拣槽的硬件，走独立串口，药品落下后发送一行包含约定标记（如 `DROP`）的文本 |
| 落药信号   | 投放结束后的检测时间窗内，传感器串口出现包含约定标记的文本行，判定“这一盒已落下” |
| 落药模拟   | 软件方式的落药检测实现。每次投放按配置的成功率（0-100%）独立判断一次，用于无硬件演示 |
| 传感器故障 | 同一药品连续漏抓达到配置上限（默认 3 次），判定传感器或机械异常：明细置“异常”、任务置“部分异常”并停止配药 |

## 4. 功能需求

### 4.1 固定处方维护模块

- **FR-1.1** 支持固定处方的新增、修改和删除。处方名称全库唯一、不超过 50 个字符、不能为空。
- **FR-1.2** 处方明细的药品下拉框只包含“启用”且“已绑定左/右药位”的药品；数量在 1 到 99 之间；同一张处方内同一种药只能出现一次，再次添加同一种药时直接修改其数量。
- **FR-1.3** 已有配药记录（待配任务）的处方不允许删除，保证历史任务仍可回看处方内容。
- **FR-1.4** 新增、修改、删除处方写入“处方管理”日志，内容包含处方名称与明细摘要（药品 × 数量）。

### 4.2 药品字典管理模块

- **FR-2.1** 支持对库存药品基础档案的新增、修改、查询。药品编号由数据库自动生成，界面只读，不允许手工修改。
- **FR-2.2** 引入“软删除”机制，支持切换药品“停用/启用”状态代替物理删除，确保历史任务与日志数据完整。停用后药品不再出现在处方维护的可选下拉中。
- **FR-2.3** 新增或编辑药品时可绑定“左侧药位”或“右侧药位”，也可不绑定；绑定关系只在药品字典页面维护。
- **FR-2.4** 支持按药品编号、药品名称或规格关键字查询，留空查询全部。

### 4.3 工位指令配置模块

- **FR-3.1** 系统内置三条物理工位数据：正前分拣槽、左侧药位、右侧药位。
- **FR-3.2** 提供工位配置界面，只维护每个工位的抓取指令、放置指令和动作延时；药品绑定不再放在本页面。
- **FR-3.3** 支持为每个工位设置抓取/放置触发宏指令（对应的底层 `$DGT` 指令字符串）和预估动作时长（毫秒）。

### 4.4 待配任务队列模块（并入配药监控看板）

- **FR-4.1** 加入队列只需填写患者编号并选择一张已保存的固定处方，录入区位于配药监控看板右侧（处方下拉 + 患者编号 + 明细预览）。加入时把处方明细（药品和数量）复制到任务明细，原处方保持不变，同一张处方可反复加入队列；配药进行中加入任务不打断当前处方，仅刷新待配队列。
- **FR-4.2** 看板下方的待配队列按“队列顺序、接收时间、任务编号”排序展示。“置顶”取当前最小队列序号减 1，使该任务排在队首。
- **FR-4.3** “撤销”只允许撤销“待配药”状态的任务，撤销后不再执行配药。
- **FR-4.4** 看板的“历史任务”按钮打开独立查询窗口，支持按任务编号和日期范围查询历史任务（包含已完成、部分异常等全部状态）。可基于选中的历史任务“再次配药”，按同一患者和处方重新生成一条待配任务，原记录保持不变。
- **FR-4.5** 加入队列、置顶、撤销写入“处方管理”日志。

### 4.5 机械臂动作触发模块

- **FR-5.1** 封装“抓取+分拣”复合业务方法：系统按药品查询对应工位 → 将该工位的 `$DGT` 编号展开为舵机帧逐帧下发 → 按工位预估时间在后台等待 → 再展开并下发正前分拣槽的放置动作 → 等待动作完成。等待在后台线程执行，不得冻结主界面。
- **FR-5.2** 支持开机复位和急停复位。系统启动时和点击急停后，下发 G0002 对应的完整 6 帧舵机指令，让机械臂回到待机姿态。急停必须能中断任意正在进行中的动作等待（至少每 50 毫秒检查一次停止标记）。
- **FR-5.3** 串口连接成功后自动开启一次连续配药会话，操作员无需再次点击；串口未连接时不能开始配药。
- **FR-5.4** 当前任务完成后，系统按队列顺序自动读取下一任务；没有任务时进入“等待新任务”，约每 1 秒刷新一次，新增任务后自动启动。
- **FR-5.5** 急停、取消“取走药品”确认或程序退出后，任务保持“配药中”或“部分异常”。重启后优先续接这些未完成任务，并按明细已记录的 `GrabCount` 只补抓剩余数量，不重复已完成抓取；指令不完整或药品未绑定药位的任务记录日志后跳过，不阻塞后续任务。

### 4.6 落药检测与异常处理模块（核心闭环）

- **FR-6.1 [逐次确认]** 每次投放后进入落药检测：投放前先清空检测通道旧信号，防止上一盒被计入本次；投放结束后的检测时间窗（默认 1500 毫秒）内等到一次落药信号，明细的实际数量 `ActualQty` 才加 1。
- **FR-6.2 [漏抓自动补抓]** 未检测到落药时，该次抓取判定无效（抓取次数照常累加），系统自动对同一种药重新抓取，直到实际数量达到应取数量。每次漏抓写入“异常纠偏”日志。
- **FR-6.3 [传感器故障拦截]** 同一药品连续漏抓达到配置上限（默认 3 次）时，判定传感器或机械异常：明细状态置“异常”、任务状态置“部分异常”，停止配药并写入“传感器故障”日志。排除故障后手动再次开始即可续接。
- **FR-6.4 [取走确认]** 任务全部明细核对通过后，系统弹出“取走药品”窗口；只有人工点击确定，才认为分拣槽清空并继续下一任务；取消则连续配药暂停，可手动再次开始。
- **FR-6.5 [双检测源]** 落药检测源支持两种形态：独立串口传感器（识别包含配置标记（默认 `DROP`）的文本行），或成功率模拟（0-100%，用于无硬件演示）。两者由配置切换，配药流程不分支。
- **FR-6.6** 每次投放的结果写入日志：检测到落药写“数量核对”（含应取/实收），漏抓或传感器故障写“异常纠偏”（含抓取次数与当前实收）。

### 4.7 处方进度与日志跟踪模块

- **FR-7.1** 看板可视化当前任务的配药进度：明细“通过数/总数”、每种药的应取数量、已执行抓取次数与当前状态，正在作业的行高亮；看板下方同步展示待配任务队列，右侧为任务录入区。机械臂作业方向（左侧药位 / 右侧药位 / 正前分拣槽）写入看板日志，不再使用工位指示图形。
- **FR-7.2** 任务总体状态为：待配药 / 配药中 / 部分异常 / 已完成 / 已撤销；看板对中断未续接的任务显示“已暂停”。
- **FR-7.3** 记录指令执行日志：时间戳、下发的宏指令（抓取与投放分开记录）、关联的任务明细。
- **FR-7.4** 日志类型共七种：药品维护 / 工位配置 / 指令下发 / 数量核对 / 异常纠偏 / 处方管理 / 账号管理；支持组合条件查询、分页浏览和 Excel 导出。

### 4.8 登录模块（单人使用）

- **FR-8.1** 程序启动先进入登录窗口，账号密码错误或账号停用不能进入主界面。
- **FR-8.2** 单人使用：登录后全部菜单可用，不再按角色过滤菜单；急停按钮始终可见。
- **FR-8.3** 密码使用 PBKDF2 加独立随机盐多次迭代哈希保存，数据库和界面都不保存明文；登录成功写入“账号管理”日志。
- **FR-8.4** 数据库初始化提供管理员 `admin`，初始密码 `Admin@123`；同名账号已存在时不覆盖密码。程序打开登录页时自动创建账号表并补写管理员账号。系统不再提供账号新增、角色调整与启停维护界面。

## 5. 非功能需求

| **类别**   | **需求描述**                                                 |
| ---------- | ------------------------------------------------------------ |
| 可靠性     | 串口下发一组动作后，按工位配置的预估时间（默认 6000 毫秒）在后台线程等待机械臂做完。等待期间主界面与急停按钮保持可操作，急停可提前结束等待（至少每 50 毫秒检查一次停止标记）。 |
| 准确性     | 落药确认是逐次投放的强制卡点：只有收到落药信号才计入实际数量，未检测到自动补抓；连续漏抓达到上限按传感器故障停止配药，防止传感器失效时机械臂盲目重复抓取。 |
| 可维护性   | 串口通信、落药检测、密码哈希、数据访问与业务流转采用分层架构封装（UI / BLL / DAL / Model / Common 五个工程）。两种落药检测源统一在 `IDropDetector` 接口之后，切换不改配药流程。 |
| 安全性     | 未登录不能进入主界面。密码只保存 PBKDF2 哈希，停用账号不能登录。单人使用的上位机仅保留初始管理员账号。 |
| 数据一致性 | 每次抓取/投放完成后，明细的 `GrabCount`、`ActualQty` 与状态立即落库；急停或程序退出后重启，可按剩余数量继续。 |

## 7. 数据库表结构

## 8. 机械臂通信协议与预设动作映射清单

本系统按“工位动作组”映射下发指令。控制板只认 `#000P1500T1000!` 形式的舵机帧，因此上位机在下发前必须按控制器 INI 展开，只发送 0 至 5 号已安装舵机，未安装轴不发送。内置动作映射：

| **业务意图**         | **动作方向** | **底层 INI 动作帧** | **工位表保存编号** | **实际串口内容**                                        |
| -------------------- | ------------ | ------------------- | ------------------ | ------------------------------------------------------- |
| **上电待机/急停**    | 中性复位     | `G0002`             | 不存，代码固定     | G0002 的 6 帧舵机指令：`#000P1500T1000!#001P1500T1000!#002P2300T1000!#003P1000T1000!#004P1500T1000!#005P1500T1000!` |
| **分拣槽抓取物料**   | 正前         | `G0003 - G0007`     | `$DGT:3-7,1!`      | 逐帧发送 G0003 至 G0007 共 5 帧                          |
| **分拣槽放下**       | 正前         | `G0008 - G0012`     | `$DGT:8-12,1!`     | 逐帧发送 G0008 至 G0012 共 5 帧                          |
| **药位 A 抓取**      | 左侧         | `G0013 - G0017`     | `$DGT:13-17,1!`    | 逐帧发送 G0013 至 G0017 共 5 帧                          |
| **药位 B 抓取**      | 右侧         | `G0023 - G0027`     | `$DGT:23-27,1!`    | 逐帧发送 G0023 至 G0027 共 5 帧                          |

### 8.1 落药检测通道协议

- **传感器模式**：落药传感器接独立串口（不得与机械臂共用）。串口参数（波特率、数据位、停止位、校验位）均可配置。药品落入分拣槽后，传感器发送一行包含约定标记（默认 `DROP`）的文本。
- **检测时序**：投放前先清空接收缓冲区（防止上一盒的信号计入本次）→ 投放动作结束进入检测时间窗（默认 1500 毫秒）→ 窗内出现包含标记的文本行，判定本颗“已落下”；窗口超时无信号，判定“漏抓”。
- **模拟模式**：不打开串口。每次投放按配置的成功率（0-100%，默认 90%）独立随机判定一次，用于无硬件环境演示漏抓补抓流程。

## 9. 关键业务流程（连续配药）

1. 登录进入主界面，系统后台打开机械臂串口；成功后先下发 G0002 待机指令，再自动开启一次连续配药（串口未连接则不能开始）。
2. 读取队首任务：优先级为“配药中”＞“部分异常”＞“待配药”，同级按队列顺序、接收时间排序；指令不完整或药品未绑定药位的任务，记录日志后跳过并继续读取下一条。
3. 将当前任务置为“配药中”；若之前中断过，写入“从中断处继续配药”日志。
4. 取第一个未“核对通过”的明细执行：
   - 将该药位抓取编号展开为舵机帧逐帧下发，按工位预估时间在后台等待；
   - 投放前清空落药检测旧信号，再展开正前分拣槽放置编号逐帧下发，等待动作完成；
   - 进入检测时间窗等待落药信号：收到则明细实际数量加 1；未收到记录漏抓并返回重新抓取；
   - 连续漏抓达到上限：明细置“异常”、任务置“部分异常”，停止配药（等待排除故障后手动开始）；
   - 实际数量达到应取数量：明细状态置“核对通过”。
5. 重复步骤 4，直到任务全部明细通过；任务总体状态置“已完成”，记录完成时间。
6. 弹出“取走药品”确认：人工取药并点击确定后继续下一任务；取消则连续配药暂停（任务状态不变，手动开始后可从中断点继续）。
7. 无待配任务时界面显示“等待新任务”，约每 1 秒刷新一次；新增任务后自动接管启动。
8. 任意时刻急停：中断当前动作等待 → 下发 G0002 恢复待机 → 任务保持“配药中/部分异常”；重启后优先续接这些未完成任务，按各明细 `GrabCount` 只补抓剩余数量。

## 11. 验收标准

- **映射下发验证**：任务要求左侧药品时，机械臂严格执行左侧抓取宏动作；右侧同理；放置动作统一在正前分拣槽执行。
- **指令格式验证**：串口实际发出的是舵机帧，不能直接发送 `$DGT` 字符串；日志中按抓取编号、投放编号分开记录。
- **动作一致性验证**：下发一组动作后上位机按预估时间后台等待机械臂完成，等待期间主界面和急停按钮保持可操作。
- **连续队列验证**：串口连接成功后自动启动；多个任务按队列顺序自动接力；配药中新增的任务自动接管；急停后可手动重新开始。
- **中断恢复验证**：急停或程序退出后再次启动，优先续接“配药中/部分异常”任务，只补抓剩余数量，不重复已完成抓取。
- **落药闭环验证**：投放后收到落药信号才计入实际数量；未检测到落药时系统自动补抓；实际数量达到应取数量后才进入下一明细。
- **异常拦截验证**：同一药品连续漏抓达到配置上限时，明细置“异常”、任务置“部分异常”，机械臂停止工作；排除故障后可再次开始并续接。
- **取走确认验证**：任务全部核对通过后，不手动确认“取走药品”不能继续下一任务。
- **登录验证**：未登录不能进入主界面；初始管理员账号可正常登录；登录后全部菜单可用。
