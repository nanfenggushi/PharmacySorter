# 医院药品分拣系统 需求说明书 (基于预设动作组版)

版本：V2.3 (新增登录与账号角色管理)

编制日期：2026-09-27

## 1. 项目背景与目标

### 1.1 项目背景

医院药房传统配药流程依赖人工按处方逐一取药，效率低、易出现药品拿错的风险，且缺乏配药过程的数据记录，一旦出现问题难以追溯具体环节。   

本项目拟设计并实现一套医院药品分拣系统。考虑到实际开发成本与硬件约束，系统将通过上位机软件控制 3D 打印双轴机械臂，充分利用机械臂控制器内已固化的“预设动作组”宏指令完成药品的抓取与分拣放置。系统将处方信息、机械臂执行状态、核对结果及数量纠偏过程全程记录到数据库中，实现配药流程的半自动化与可追溯。   

### 1.2 项目目标

- 基于控制板预设的三组作业方向（前、左、右），实现机械臂根据处方单自动完成"触发特定方向抓取 → 触发正前方分拣槽放置"的动作序列。   
- 建立药品与固定物理工位（左药位/右药位）的映射关系。   
- 记录每条机械臂宏指令的下发状态，提供处方级别的配药进度与完成状态跟踪。   
- 取药完成后进行人工数量核对，并支持“漏抓自动补缺”与“多抓强制物理剔除”的闭环处理机制。   

### 1.3 适用范围

本系统面向课程设计/毕业设计/个人练习项目场景。物理场景限定为 1 个分拣槽与 2 个药品货位。上位机保存 `$DGT` 动作组编号，真正发给控制板的是对应动作帧里的 `#000P1500T1000!` 舵机指令。系统不涉及六轴实时角度逆解计算与底层的防撞轨迹规划。  

## 2. 项目范围

### 包含内容

- 上位机软件（C# WinForms + SQL Server 开发环境）   
- 处方信息解析与待配药品清单生成   
- 药品字典的基础数据维护与软删除管理
- 登录认证，以及管理员、药师、操作员三种角色的菜单权限
- 账号的新增、角色调整、启停和密码维护
- 药品与固定物理工位（左、右）的绑定维护   
- 基于预设宏指令的串口通信触发与固定动作延时控制   
- 配药执行状态跟踪与人工数量核对补偿机制   
- 指令下发与操作日志记录、查询   

### 不包含内容

- 六轴机械臂底层驱动与空间三维坐标系的标定算法开发   
- 多机械臂协同调度   
- 真实药品识别/称重传感器算法开发（当前版本依赖人工比对输入实际数量）   

## 3. 术语定义

| **术语**   | **说明**                                                     |
| ---------- | ------------------------------------------------------------ |
| 上位机     | 运行本系统的电脑端软件，负责业务逻辑控制、数据存储与宏指令触发下发 |
| 预设动作组 | 机械臂控制器内预先烧录好的连贯动作序列（如 `G0003-G0007` 组成的一个完整“前抓”动作流） |
| 固定工位   | 机械臂动作预设所能覆盖的 3 个有效作业区域，划分为：正前分拣位、左侧药位、右侧药位。 |
| 触发宏指令 | 工位表中保存的动作组编号（如 `$DGT:13-17,1!`）。控制板不能直接执行该字符串，上位机发送前要展开成 G0013 至 G0017 的舵机帧 |

## 4. 功能需求

### 4.1 处方管理模块

- **FR-1.1** 支持手动录入处方信息：处方号、患者信息（可简化为编号）、开具时间。   
- **FR-1.2** 支持录入处方明细：药品编号、药品名称、需取数量。   
- **FR-1.3** 维护待配处方队列，支持按接收时间排序。   
- **FR-1.4** 支持按处方号/时间范围查询历史处方记录。   

### 4.2 药品字典管理模块 (新增)

- **FR-2.1** 支持在库药品基础档案的增删改查（CRUD）操作。
- **FR-2.2** 引入“软删除”机制，支持对药品进行“停用/启用”状态切换，以替代物理删除，保障历史处方数据与日志的完整性。
- **FR-2.3** 处方录入时，系统仅允许选择状态为“已启用”的药品。
- **FR-2.4** 新增和编辑药品时，可将其绑定至“左侧药位”或“右侧药位”，也可以保持未绑定。绑定关系只在药品字典维护。

### 4.3 工位指令配置模块

- **FR-3.1** 系统内置 3 个物理工位数据：正前分拣槽、左侧药位、右侧药位。
- **FR-3.2** 提供工位配置界面，只维护各工位的抓取指令、放置指令和动作延时，不再在本页绑定药品。
- **FR-3.3** 支持配置各工位对应的抓取与放置触发宏指令（对应底层的 `$DGT` 指令串）。

### 4.4 机械臂动作触发模块

- **FR-4.1** 封装"抓取+分拣"复合业务方法：系统查询药品对应工位 → 将该工位的 `$DGT` 编号展开成舵机帧并逐帧下发 → 按工位预估时间等待 → 再展开并下发正前方分拣槽放置动作 → 等待动作执行完毕。等待放在后台执行，不能卡住主界面。
- **FR-4.2** 支持开机复位和急停复位。系统启动时以及点击急停后，下发 G0002 对应的完整 6 舵机指令，使机械臂进入待命姿态。急停要能打断正在进行的动作等待。
- **FR-4.3** 按处方明细逐条药品循环调用动作组合，直至实际动作次数达到处方要求数量。
- **FR-4.4** 串口连接成功后自动启动一次连续配药，不需要操作员再点击。当前处方完成后，系统按队列顺序自动读取下一张；暂时没有处方时进入“等待新处方”，新处方提交后自动开始。急停会中断本次循环，按钮恢复后可手动再次启动。
- **FR-4.5** 急停、关闭核对窗口或程序退出后，处方保持“配药中”或“部分异常”。再次启动时优先继续这些未完成处方，并按明细已记录的 `GrabCount` 补抓剩余数量，不重复已完成的抓取。指令不完整或药品未绑定药位的处方写入日志后跳过，不阻塞后续处方。

### 4.5 核对与异常处理模块（核心纠错机制）

- **FR-5.1** 单种药品取药循环完成后，系统暂停并要求人工输入分拣槽内的实际药品数量。   
- **FR-5.2 [漏抓补缺]** 当人工填写的实收数量小于处方要求数量时，系统自动计算差额，弹窗询问是否补抓。人工确认后，上位机自动追加下发对应次数的抓放动作流。   
- **FR-5.3 [多抓拦截]** 当人工填写的实收数量大于处方要求数量时，系统触发红灯警报并锁定流程。界面提示人工物理剔除多余药品，必须由人工勾选“已物理清除多余药品”复选框后，系统方可放行。   
- **FR-5.4 [严重重置]** 支持人工一键“作废重置”当前药品进度。触发后该明细已执行次数清零，状态恢复为“待取药”，需人工清空分拣槽后由系统重新抓取。   
- **FR-5.5** 处方所有明细最终核对通过后，将处方整体状态置为"配药完成"。   

### 4.6 处方进度与日志跟踪模块

- **FR-6.1** 界面可视化展示每张处方的配药进度（已完成条数/总条数）。   
- **FR-6.2** 展示处方整体状态：待配药/配药中/部分异常/已完成。   
- **FR-6.3** 记录指令执行日志：时间戳、下发的宏指令内容、关联处方明细。   
- **FR-6.4** 记录异常干预日志：记录漏抓补缺次数或超量强制剔除的确认时间。   


### 4.7 登录与账号角色模块

- **FR-7.1** 启动程序先进入登录窗口。账号或密码错误、账号已停用时不能进入主界面。
- **FR-7.2** 系统固定三种角色：管理员、药师、操作员。管理员可使用全部菜单；药师可维护药品字典和处方；操作员可使用配药看板和急停。
- **FR-7.3** 管理员可新增账号。登录账号长度为 3 到 50 个字符，初始密码长度为 8 到 50 个字符，两次输入必须一致。下方表格是否选中已有账号，不影响新增。
- **FR-7.4** 管理员可修改选中账号的姓名、角色、启用状态和密码。登录账号创建后不能修改。两个密码框都留空表示不修改密码。
- **FR-7.5** 至少保留一个启用的管理员。停用最后一个管理员或将其改为其他角色时，系统拒绝保存。
- **FR-7.6** 密码使用 PBKDF2 加独立随机盐保存，数据库和界面都不保存明文。登录、新增、修改账号写入“账号管理”日志。

## 5. 非功能需求

| **类别**   | **需求描述**                                                 |
| ---------- | ------------------------------------------------------------ |
| 可靠性     | 串口下发一组动作后，按工位配置的预估时间等待机械臂做完，默认一组动作 6000 毫秒。等待期间界面保持可操作，急停可以提前结束等待。 |
| 准确性     | 取药数量人工输入与校验为强制卡点环节，未确认实际数量一致前不允许自动进入下一种药品的抓取。 |
| 可维护性   | 串口通信、数据访问、业务流转需采用分层架构封装，避免代码过度耦合于 WinForms 界面中。 |
| 安全性     | 未登录不能进入主界面。密码只保存哈希，停用账号不能登录，系统始终保留至少一个启用的管理员。 |
| 数据一致性 | 数据库处方明细状态必须与机械臂当前执行的进度保持严格同步。   |

## 8. 机械臂通信协议与预设动作映射清单

本系统在工位表中保存动作组编号。控制板只识别 `#000P1500T1000!` 形式的舵机帧，因此上位机发送前必须按控制器 INI 把编号展开。只下发 0 至 5 号舵机，未安装的舵机不发送。系统内置必须遵循以下协议：

| **业务意图** | **动作方向** | **底层 INI 动作帧** | **工位表保存的编号** | **实际串口内容** |
| --- | --- | --- | --- | --- |
| **开机待命/急停** | 中立 | `G0002` | 不保存，代码固定拼装 | G0002 的 6 个舵机帧。底座回中，大臂与小臂抬到安全高度，夹爪张开 |
| **分拣槽取料** | 正前方 | `G0003 - G0007` | `$DGT:3-7,1!` | 逐帧发送 G0003 至 G0007 |
| **分拣槽投递** | 正前方 | `G0008 - G0012` | `$DGT:8-12,1!` | 逐帧发送 G0008 至 G0012 |
| **药位A取料** | 左侧 | `G0013 - G0017` | `$DGT:13-17,1!` | 逐帧发送 G0013 至 G0017 |
| **药位B取料** | 右侧 | `G0023 - G0027` | `$DGT:23-27,1!` | 逐帧发送 G0023 至 G0027 |

## 9. 关键业务流程 (连续配药)

1. 处方接收，系统将其状态置为"待配药"，生成需处理的处方明细列表。
2. 串口连接成功后自动启动连续配药。系统先下发 G0002 待命指令，然后持续读取队列。串口未连接时不启动。
3. 若当前处方是“配药中”或“部分异常”，从已记录的抓取次数继续；否则将队首“待配药”处方改为“配药中”。
4. 系统取第一条尚未核对通过的药品，查询其关联的 `StationId`。
5. 上位机把该药位的 `$DGT` 编号展开为舵机帧并逐帧发送，按工位预估时间在后台等待。
6. 上位机再把正前方分拣槽的放置编号展开并发送，再次等待动作完毕。抓取和投递分别写入日志。
7. 循环执行步骤 5-6，直到该药品实际机械动作次数达到处方要求数量。
8. **[人工强制核对阶段]** 系统弹出核对窗口，请求人工盘点分拣槽内实际掉落的药品数量。
   - **分支 A (一致)**：人工输入数量 = 应发数量。该明细状态置为"核对通过"。
   - **分支 B (漏抓)**：人工输入数量 < 应发数量。系统自动计算差额，再次循环步骤 5-6 执行补缺动作，完成后重新回到步骤 8 盘点。
   - **分支 C (多抓)**：人工输入数量 > 应发数量。流程锁定并标红，人工将多余药品拿走后，必须强制勾选“已剔除多余药品”按钮方可放行。该明细修改实际数量并置为"核对通过"。
9. 重复步骤 4-8 直至该处方所有药品明细处理完毕。全部通过后，处方整体状态置为"已完成"。
10. 自动读取下一张处方并重复步骤 3-9。没有处方时显示“等待新处方”，约每秒刷新一次；收到急停或出现不能继续的错误时停止。

## 10. 验收标准

- **映射调度验证**：当处方需要左侧药品时，机械臂严格执行向左旋转的宏动作；需要右侧时严格向右，投递动作统一回正前方执行。
- **指令格式验证**：串口实际发出的是舵机帧，不直接发送 `$DGT` 字符串。日志仍分别记录抓取编号和投递编号。
- **动作一致性验证**：发送一组动作后，上位机在后台等待机械臂做完。等待期间主界面和急停按钮保持可操作。
- **连续队列验证**：串口连接成功后自动启动，多张处方按队列自动执行。配药过程中新提交的处方会被自动接上。急停后可手动再次启动。
- **中断恢复验证**：急停或关闭程序后再次启动，系统优先继续“配药中”处方，并只补抓剩余数量。
- **自动补抓验证**：在核对环节输入小于应发数量的数值，系统能自动判定差额，并指挥机械臂准确补抓缺少的数量。
- **异常拦截验证**：在核对环节输入大于应发数量的数值，系统界面强制锁定，成功阻止机械臂继续作业，直到人工确认剔除完毕。
