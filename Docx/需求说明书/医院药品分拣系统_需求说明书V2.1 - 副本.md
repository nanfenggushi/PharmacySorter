- # 医院药品分拣系统 需求说明书 (基于预设动作组版)

  版本：V2.1 (含核对纠错机制)

  编制日期：2026-09-18

  ## 1. 项目背景与目标

  ### 1.1 项目背景

  医院药房传统配药流程依赖人工按处方逐一取药，效率低、易出现药品拿错的风险，且缺乏配药过程的数据记录，一旦出现问题难以追溯具体环节。   

  本项目拟设计并实现一套医院药品分拣系统。考虑到实际开发成本与硬件约束，系统将通过上位机软件控制 3D 打印双轴机械臂，充分利用机械臂控制器内已固化的“预设动作组”宏指令完成药品的抓取与分拣放置。系统将处方信息、机械臂执行状态、核对结果及数量纠偏过程全程记录到数据库中，实现配药流程的半自动化与可追溯。   

  ### 1.2 项目目标

  - 基于控制板预设的三组作业方向（前、左、右），实现机械臂根据处方单自动完成"触发特定方向抓取 → 触发正前方分拣槽放置"的动作序列。   
  - 建立药品与固定物理工位（左药位/右药位）的映射关系。
  - 记录每条机械臂宏指令的下发状态，提供处方级别的配药进度与完成状态跟踪。   
  - 取药完成后进行人工数量核对，并支持“漏抓自动补缺”与“多抓强制物理剔除”的闭环处理机制。   

  ### 1.3 适用范围

  本系统面向课程设计/毕业设计/个人练习项目场景。物理场景限定为 1 个分拣槽与 2 个药品货位。上位机与机械臂之间通过串口通信下发动作组唤醒字符串（如 `$DGT` 指令），不涉及六轴实时角度逆解计算与底层的防撞轨迹规划。   

  ## 2. 项目范围

  ### 包含内容

  - 上位机软件（C# WinForms + SQL Server 开发环境）   
  - 处方信息解析与待配药品清单生成   
  - 药品与固定物理工位（左、右）的绑定维护
  - 基于预设宏指令的串口通信触发与固定动作延时控制
  - 配药执行状态跟踪与人工数量核对补偿机制   
  - 指令下发与操作日志记录、查询   

  ### 不包含内容

  - 六轴机械臂底层驱动与空间三维坐标系的标定算法开发   
  - 多机械臂协同调度   
  - 真实药品识别/称重传感器算法开发（当前版本依赖人工比对输入实际数量）   

  ## 3. 术语定义

  | **术语**   | **说明**                                                     |
  | ---------- | ------------------------------------------------------------ |
  | 上位机     | 运行本系统的电脑端软件，负责业务逻辑控制、数据存储与宏指令触发下发 |
  | 预设动作组 | 机械臂控制器内预先烧录好的连贯动作序列（如 `G0003-G0007` 组成的一个完整“前抓”动作流） |
  | 固定工位   | 机械臂动作预设所能覆盖的 3 个有效作业区域，划分为：正前分拣位、左侧药位、右侧药位。 |
  | 触发宏指令 | 上位机向串口发送的简短控制字符串（如 `$DGT:13-17,1!`），用于一键唤醒机械臂执行对应的动作组 |

  ## 4. 功能需求

  ### 4.1 处方管理模块

  - **FR-1.1** 支持手动录入处方信息：处方号、患者信息（可简化为编号）、开具时间。   
  - **FR-1.2** 支持录入处方明细：药品编号、药品名称、需取数量。   
  - **FR-1.3** 维护待配处方队列，支持按接收时间排序。   
  - **FR-1.4** 支持按处方号/时间范围查询历史处方记录。   

  ### 4.2 药品-工位映射模块

  - **FR-2.1** 系统内置 3 个物理工位数据：正前分拣槽、左侧药位、右侧药位。
  - **FR-2.2** 提供工位配置界面，支持将具体药品绑定至"左侧药位"或"右侧药位"。
  - **FR-2.3** 支持配置各工位对应的抓取与放置触发宏指令（对应底层的 `$DGT` 指令串）。

  ### 4.3 机械臂动作触发模块

  - **FR-3.1** 封装"抓取+分拣"复合业务方法：系统查询药品对应工位 → 串口下发该工位抓取宏指令 → 线程休眠等待动作执行完毕 → 串口下发正前方分拣槽放置宏指令 → 线程休眠等待动作执行完毕。
  - **FR-3.2** 支持开机复位控制，每次系统启动及处方开始前下发复位指令，使机械臂进入待命姿态（对应指令 `G0002`）。   
  - **FR-3.3** 按处方明细逐条药品循环调用动作组合，直至实际动作次数达到处方要求数量。   

  ### 4.4 核对与异常处理模块（核心纠错机制）

  - **FR-4.1** 单种药品取药循环完成后，系统暂停并要求人工输入分拣槽内的实际药品数量。   
  - **FR-4.2 [漏抓补缺]** 当人工填写的实收数量小于处方要求数量时，系统自动计算差额，弹窗询问是否补抓。人工确认后，上位机自动追加下发对应次数的抓放动作流。
  - **FR-4.3 [多抓拦截]** 当人工填写的实收数量大于处方要求数量时，系统触发红灯警报并锁定流程。界面提示人工物理剔除多余药品，必须由人工勾选“已物理清除多余药品”复选框后，系统方可放行。   
  - **FR-4.4 [严重重置]** 支持人工一键“作废重置”当前药品进度。触发后该明细已执行次数清零，状态恢复为“待取药”，需人工清空分拣槽后由系统重新抓取。   
  - **FR-4.5** 处方所有明细最终核对通过后，将处方整体状态置为"配药完成"。   

  ### 4.5 处方进度与日志跟踪模块

  - **FR-5.1** 界面可视化展示每张处方的配药进度（已完成条数/总条数）。   
  - **FR-5.2** 展示处方整体状态：待配药/配药中/部分异常/已完成。   
  - **FR-5.3** 记录指令执行日志：时间戳、下发的宏指令内容、关联处方明细。   
  - **FR-5.4** 记录异常干预日志：记录漏抓补缺次数或超量强制剔除的确认时间。

  ## 5. 非功能需求

  | **类别**   | **需求描述**                                                 |
  | ---------- | ------------------------------------------------------------ |
  | 可靠性     | 串口下发宏指令后，需设置合理的程序延时（如 3-5 秒）以确保机械臂充分执行完毕动作组，避免指令拥堵重叠。 |
  | 准确性     | 取药数量人工输入与校验为强制卡点环节，未确认实际数量一致前不允许自动进入下一种药品的抓取。 |
  | 可维护性   | 串口通信、数据访问、业务流转需采用分层架构封装，避免代码过度耦合于 WinForms 界面中。 |
  | 数据一致性 | 数据库处方明细状态必须与机械臂当前执行的进度保持严格同步。   |

  ## 8. 机械臂通信协议与预设动作映射清单

  本系统直接下发触发字符串，唤醒机械臂底层的预录动作帧以完成复杂作业。系统内置必须遵循以下协议：   

  | **业务意图**   | **动作方向** | **底层 INI 动作帧** | **上位机串口下发字符串**  | **动作流行为说明**                             |
  | -------------- | ------------ | ------------------- | ------------------------- | ---------------------------------------------- |
  | **开机待命**   | 中立         | `G0002`             | `(拼装G0002直接数值指令)` | 机械臂抬起到安全高度，张开夹爪准备作业。       |
  | **分拣槽取料** | 正前方       | `G0003 - G0007`     | `$DGT:3-7,1!`             | 朝正前方降下手臂，闭合爪子抓取，随后抬起归位。 |
  | **分拣槽投递** | 正前方       | `G0008 - G0012`     | `$DGT:8-12,1!`            | 朝正前方降下手臂，张开爪子松开，随后抬起归位。 |
  | **药位A取料**  | 左侧         | `G0013 - G0017`     | `$DGT:13-17,1!`           | 云台向左旋转，降下手臂抓取，随后抬起归位。     |
  | **药位B取料**  | 右侧         | `G0023 - G0027`     | `$DGT:23-27,1!`           | 云台向右旋转，降下手臂抓取，随后抬起归位。     |

  ## 9. 关键业务流程 (单张处方配药)

  1. 处方接收，系统将其状态置为"待配药"，生成需处理的处方明细列表。   
  2. 启动配药任务，下发 `G0002` 对应的待命指令使机械臂进入初始安全状态。   
  3. 系统取第一条尚未处理的药品，查询其关联的 `StationId`。
  4. 上位机向串口发送对应的抓取指令 `$DGT:13-17,1!`，利用线程阻塞延时等待机械臂动作完成。
  5. 上位机向串口发送正前方分拣槽放置指令 `$DGT:8-12,1!`，再次延时等待动作完毕。   
  6. 循环执行步骤 4-5，直到该药品实际机械动作次数达到处方要求数量。
  7. **[人工强制核对阶段]** 系统界面挂起，弹窗请求人工盘点分拣槽内实际掉落的药品数量。   
     - **分支 A (一致)**：人工输入数量 = 应发数量。该明细状态置为"核对通过"[cite: 2]。
     - **分支 B (漏抓)**：人工输入数量 < 应发数量。系统自动计算差额，再次循环步骤 4-5 执行补缺动作，完成后重新回到步骤 7 盘点。
     - **分支 C (多抓)**：人工输入数量 > 应发数量。流程锁定并标红，人工将多余药品拿走后，必须强制勾选“已剔除多余药品”按钮方可放行[cite: 2]。该明细修改实际数量并置为"核对通过"[cite: 2]。
  8. 重复步骤 3-7 直至处方所有药品明细处理完毕。全部通过后，处方整体状态置为"已完成"[cite: 2]。

  ## 10. 验收标准

  - **映射调度验证**：当处方需要左侧药品时，机械臂严格执行向左旋转的宏动作；需要右侧时严格向右，投递动作统一回正前方执行。
  - **动作一致性验证**：发送宏指令后，上位机通过延时机制保证机械臂动作完整执行不被打断，无明显的逻辑卡死现象。
  - **自动补抓验证**：在核对环节输入小于应发数量的数值，系统能自动判定差额，并指挥机械臂准确补抓缺少的数量。
  - **异常拦截验证**：在核对环节输入大于应发数量的数值，系统界面强制锁定，成功阻止机械臂继续作业，直到人工确认剔除完毕[cite: 2]。
